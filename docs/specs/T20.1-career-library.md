# T20.1 career library foundation

Status: implemented and validated locally; production approval pending. Parent T20
remains incomplete. Branch: claude/trim-drop-radar-plan. Version: 0.20.0.

The [adopted goal](GOAL.md) needs private evidence shared by ranking, resumes,
applications and outreach. This first foundation adds the Career screen and a
versioned fact/answer API. It does not complete all T20.1 packet/action foundations.

## Behavior

- Owner-scoped facts and reusable answers; no guest or cross-user reads/writes.
- Draft, approved and retired states. Approval requires a source/confirmation note;
  it is owner review, not independent verification or external-action permission.
- Answers require explicit context and may bind exact approved fact revisions.
- Immutable revisions, optimistic conflict rejection and paged library/history.
- Changed/retired supporting facts or superseded record revisions cannot be reused.
- Editing an approved record starts as a draft in the UI; errors retain current edits.
- No ingestion/filtering changes, source fetches, models or outbound actions.

## Persistence and proposed live migration

Schema 5→6 adds only empty `career_records`: user ID, record ID, revision, kind,
JSON body and creation time, with a composite primary key. Existing tables and values
are untouched. Store initialization applies the migration, so backend deployment
requires explicit live-schema approval and a SQLite online backup first.
Local migration tests compare existing jobs, actions, notes and other table rows.

## Interfaces

Authenticated GET/POST `/api/career`, PUT `/api/career/{record_id}` with expected
revision, GET `/api/career/{record_id}/history` with older-revision pagination.
OpenAPI and web types updated. `reusable` means current approved evidence only;
future consumers must still match answer context and revalidate action policy.
